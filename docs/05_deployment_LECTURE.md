# 第5章 部署与服务化（教科书式）

## 学习目标
完成本章后，你应能：
1. 比较不同部署策略（本地、容器化、云服务）的优劣；
2. 把模型封装为服务并设计基本的监控与降级策略；
3. 在资源受限环境下设计可行的部署方案并验证其性能。

---

## 1. 引言
部署是把技术变成产品的关键一环。除了模型本身，工程师必须考虑冷启动、并发、监控、错误恢复与成本控制。本章在理论与工程实践之间架桥，提供可复制的流程。

---

## 2. 部署架构要点
- 容器化与镜像管理：Dockerfile 设计、镜像体积优化、分层缓存策略；
- 服务化接口：REST / gRPC / OpenAI 兼容接口的设计要点；
- 伸缩与负载：批处理、批大小调度、并发控制、缓存（KV cache）；

---

## 3. Worked Example：从量化模型到 Docker 服务（流程）
描述：把量化后的模型放入镜像、启动服务、并用示例脚本对比 cold start 与 warm start 的 latency 差异，记录并分析结果。

---

## 4. 练习（Exercises）
1. 编写一个 Dockerfile 优化示例，使镜像体积尽可能小并保证服务可用。
2. 设计并实现一个简单的降级策略：当 qps 超过阈值时返回缓存答案或限流。
3. 实验 cold start 与 warm start，记录并分析差异原因。
4. 设计一个监控 dashboard（简单说明需要的 metric 与报警规则）。
